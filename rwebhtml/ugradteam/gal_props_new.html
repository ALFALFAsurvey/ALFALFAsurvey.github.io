Computing Galaxy properties for ALFALFA


On this page, we will develop recipes for processing ALFALFA data in a uniform manner. This needs to be a cookbook, with specific "how-to" instructions given in detail, links to references, and locations of code.

Available datasets

  • ALFALFA catalogs: The non-public versions are available to ALFALFA team members with the understanding that (a) any non-public version is not certified to be error-free and (b) non-public versions should be not be passed on to others and should be used only for projects which do not conflict with those of other members of the team. If you have questions about what you are doing, ask Riccardo or Martha. The contents of ALFALFA catalogs are explained here. Be aware that the catalog output from the ALFALFA web archive has a different format from the non-public versions.

  • The Arecibo General Catalog (AGC) is our private database containing basic data on several hundred thousand galaxies. It is not intended to be used by or distributed to people outside the ALFALFA collaboration. So, check out the conditions of use first and then follow the link there for information on the contents.

  • Compute distances and understand flow models: Recessional velocities given in the AGC/ALFALFA catalogs are heliocentric. To compute distances, you can't just plug them into Hubble's Law.

    For objects at high redshifts, it is acceptable to approximate the distance by using Hubble's Law because the object's motion is dominated by its recessional velocity. The theory behind the flow model is that the universe is not homogeneous or isotropic on a nearby scale, so for most objects in ALFALFA (z <= 0.06), the peculiar velocity component of an object is nontrivial. These peculiar velocities show "flow" towards gravitational concentrations; it is therefore necessary to create a model to account for nearby large-scale structure, such as the Virgo Attractor and the Great Attractor.

    The flow model used for ALFALFA is the one generated by Karen Masters, which models for two spherical attractors (Virgo Attractor and Great Attractor) and for a quadrupole component, which serves to correct for non-spherical attractions (since the Local Supercluster has filamentary, not spherical, structure), and to account for additional influences of outside masses. It calculates distances by matching the coordinates and velocities to the generated model. For details on the calculations of the flow model, see Karen's thesis.

    There are some caveats offered with the flow model. The reliability of the flow model used for ALFALFA depends on the part of the sky--particularly along the line of sight towards the Virgo and Great Attractors; distances to galaxies within 5 Mpc are also problematic due to being so close.

    There are several tools available to calculate distances using the flow model. distance_catalog.pro decides which distance estimation method is best for calculating and object's distance, and then proceeds to calculate the distance. The procedure checks for primary distances (distances calculated by reliable means independent of redshift, such as parallax, Cepheid variables, etc.) and uses any primary distances found, not running the flowmodel on objects with primary distances. It then checks for group assignment, and if the object is a member of a group that has a group velocity greater than 6000km/s, the distance is calculated using the group velocity and Hubble's Law. If the group velocity is less than 6000km/s, the distance is calculated using the group velocity in the flow model. If an object is not a member of a group, then the program examines the CMB velocity (velocity in frame of CMB), which was converted from the heliocentric velocity contained in the catalog. If the CMB velocity is greater than 6000km/s, the CMB velocity is used in Hubble's Law to compute distance. If the CMB velocity is less than 6000km/s, the flow model is used.

    To use distance_catalog.pro, the user specifies the (headerless) input catalog file in AGC or GALCAT format. For each object, a distance and error are calculated, and two flags are assigned: the flow model flag (which tells you whether the flow model was used to calculate the distance, and if so, whether any problems were encountered) and the distance source flag (which tells you what information was used to estimate the distance). (After running distance_catalog.pro, it is important to check these flags because some objects can have more than one distance near infall regions, and sometimes a distance of zero is calculated, which would lead to an infinite mass, which is not possible). For an AGC-formatted catalog, the output is "*.agc," a file with 7 columns: AGC number, coordinates (HHMMSSS+DDMMSS), heliocentric velocity, distance (Mpc), distance error (Mpc), flow model flag, and distance source flag. For a GALCAT-formatted catalog, there are three output files: *.info, *.table, and *.tex. The *.info file contains the same information as described for the *.agc case. The two other files, *.table and *.tex, are almost identical, except that the *.tex file includes the markup necessary to make a TEX table of the information. These files are in the table format used in ALFALFA papers: object number, AGC #, HI RA and Dec, Optical Counterpart RA & Dec, cz (km/s), W50, Sint (integrated flux, Jy km/s), Serr (Jy km/s), S/N, RMS, distance (Mpc), log(M/Msun), and code.

    Call distance_catalog as:
    IDL> distance_catalog,input_file_type,input_file_name,output_file_string
    The "input file type" is a code to let distance_catalog know whether you are using an AGC formatted catalog (in which case the input_file_type is 0) or a GALCAT formatted catalog (in which case the input_file_type is 1). Remember that the output products will depend on the catalog type. Also remember to remove header information from your catalog!

    The "input file name" is simply the name of the input file; if it's not in your current directory, include the directory structure. The "output file string" tells distance_catalog how to name the output files. It has a standard set of outputs -- including *.info -- and the "output file string" will replace the "*" in the name of each output files. If you want to place your output files outside of your current directory, include the directory structure.
    Example:
    IDL> distance_catalog,1,'mycatalog.cat','mycatalog': Will read "mycatalog.cat" and output mycatalog.info, mycatalog.tex, and mycatalog.table

    Flags are defined as follows:
    Flow model flag: The flow model uses codes 0,1,2,3,10,11,12,13,20,21,22,23 and 30. If the flowmodel flag is -1, that means the flowmodel was not at all employed in the distance determination for that object. Flow model flags indicate possible problems with the distance and error obtained using the flow model. IF the flow model flag is anything other than a 1, 10 or 20 is is probably worth investigating and thinking about. The flowmodel flags are defined as follows:
    0: No distance found. Usually close to D=0Mpc
    1: Everything is fine, single valued distance
    2: Double valued distance
    3: Triple valued distance
    10: Assigned to Virgo Core
    11: Near Virgo (within 6Mpc which is region where SB00 claim that model is "uncertain"), single valued
    12: Near Virgo (within 6Mpc which is region where SB00 claim that model is "uncertain"), double valued
    13: Near Virgo (within 6Mpc which is region where SB00 claim that model is "uncertain"), triple valued
    20: Assigned to GA Core
    21: Near GA (within 10Mpc which is region where SB00 claim that model is "uncertain"), single valued
    22: Near GA (within 10Mpc which is region where SB00 claim that model is "uncertain"), double valued
    23: Near GA (within 10Mpc which is region where SB00 claim that model is "uncertain"), triple valued
    30: Assigned to Core of Fornax cluster
    Distance source flag:
    The second flag indicates the source of the distance. Since each method has its advantages and disadvantages, it's wise to pay attention to this flag, especially for nearby objects.

    -1 - no distance (High Velocity Cloud)
    99 - distance estimated using pure Hubble flow, using the object's CMB rest frame velocity and a Hubble parameter H_0 = 70.0 km/s/Mpc. This applies to objects (or groups) with CMB frame velocities greater than 6000 km/s. At the moment, the error on such a distance is given as 0.
    98 - distance is from a primary distance measurement.
    97 - object belongs to a group with a CMB rest frame velocity greater than 6000 km/s, so the distance to the object was estimated using pure Hubble flow from the object's CMB frame velocity.
    96 - object belongs to a group with a CMB rest frame velocity less than 6000 km/s, so the distance to the object was estimated using the flow model and using the group's velocity.
    95 - object belongs to a group, and one member has a primary distance, so all objects in the group are assigned to that distance. ***THIS IS NOT EMPLOYED AT THE MOMENT BUT WILL BE IN THE FUTURE.***
    94 - the object does not have a primary distance measurement, and does not belong to a group, so a flow model distance is given.

  • Convert from one coordinate frame to another:
    cartcoords.pro: converts from spherical to cartesian. See cartcoords.pro in the EGGGEN library. Inputs are RA, Dec (or SG long, SG lat) in radians and radius in distance units; outputs are x, y and z in distance units.

    By far, the most useful conversions can be found in The IDL Astronomy User's Library which is installed locally at Cornell and may be used as soon as you start IDL without any extra compilations. For those not at Cornell, it is easy to download individual modules (see links below) and simply compile them in your IDL session.

    • GLACTC will convert between celestial and Galactic (or Supergalactic) coordinates for any epoch.
    • TEN will convert sexigesimal coordinates (i.e. HHMMSS.S) to decimal. Thus, coordinate conversions can be passed to GLACTC as, for example:

      glactc, ten(19,50,47),ten(8,52,6),2000,gl,gb,1
      with result gl = 47.74, gb = -8.91.

  • Calculate Galactic extinction at a location
    The DIRBE codes are located in /home/dorado3/galaxy/eggidl/dirbe, along with DIRBE maps. The relevant reference is Schlegel et al. 1998, ApJ, 500, 525. Most of the code in the above directory was provided by David Schlegel, with the exception of dirbe_bandpass.pro, written by Ann Martin. How to calculate Galactic extinction:
    1. Compile dust_getval.pro and dirbe_bandpass.pro (in /home/dor3/gal/eggidl/dirbe)
    2. Calculate your coordinates in Galactic long (l) and lat (b) in degrees. You may use the Astro User's Library (installed locally; all you need to do is start IDL) procedure GLACTC for coordinate transformations.
    3. Obtain the DIRBE E-V reddening value using the function dust_getval
      • ipath = '/home/dorado3/galaxy/eggidl/dirbe/' ;set the path to DIRBE maps
      • map='Ebv' ;designate the reddening map
      • value = dust_getval(gall,galb,/interp,ipath=ipath,map=map)
    4. Convert the E-V reddening value ("value") to the bandpass of interest
      • Look up the filter/bandpass of interest in the notes for dirbe_bandpass.pro
      • bandpass=25 ; for Sloan u -- many other filters available!
      • extinction=dirbe_bandpass(value,bandpass) ;returns the extinction in the band of interest at the coordinates
